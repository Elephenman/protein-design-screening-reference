# 发布说明：这份东西是什么、卖给谁、边界在哪

一页纸。日期 2026-11-08（公开仓库口径版）。

---

## 一句话

**一份可执行的蛋白设计筛选工作流，每个阈值都能回查到原文哪一句。**

不是综述，不是教程，是一个开工照抄的模板 + 一套能自证"我没编"的机器门禁。

---

## 卖什么（三层，按客户需要挑）

| 层 | 内容 | 形态 | 适合谁 |
|---|---|---|---|
| **L1 工作流包** | 主线十阶段模板 + 结合体/酶/肽三分支 + 多轮迭代协议 + 前沿默认链（RFD4-Proteina） | 文档 + 可编辑模板 | 刚开始做蛋白设计、需要照着走的团队 |
| **L2 证据包** | L1 + 152 张精读卡 + 证据台账 + 判据台账 + 87 行许可审计 + 224 份第三方原文清单（路径/sha256/重取方式）+ 引用预算改动账 + 全部门禁脚本 | 可复跑的工作树（第三方原文按清单重取后可复跑逐字门禁） | 要做自己体系的、且要求每个数字可回查的客户 |
| **L3 定制** | 在 L2 基础上，按客户的目标体系重校准阈值、跑参照回收、建判据台账 | 咨询 | 有具体靶点/蛋白、需要在两个月内拿到可执行门槛的客户 |

L1/L2 已由 `scripts/build_bundles.py` 生成可发布包；L3 是服务。

## 为什么有人愿意付钱

不是"我们读过 152 篇论文"，而是这三条：

1. **每个阈值带出处**。87 条默认阈值，每条标注证据级别（P0 全文逐字核验 / P1 摘要级 / P2 库外一手全文 / P3 库外仅摘要 / P4 本报告推算 / P5 未记录）并挂上 `[文献编号]`。编号在总表 CSV 里能回查到 DOI。
2. **分母不许混**。in silico 通过率、表征子集比例、末端实测池命中率是三回事。库里真实案例说明混用会怎样（`[B11]` 的"约 90% vs 约 30%"两个分母都是自选子集）。
3. **失败模式写下来了**。阈值凑池、in silico ≠ 湿实验、打分器依赖特权信息、分布外推、摘要与正文口径不一致——这些不是我们的原创发现，是从 152 篇里沉淀的缺陷清单，客户付的是"别再踩一遍"。

## 边界（不能含糊的部分）

### 证据边界

- **"能证明 / 不能证明 / 尚缺什么"** 三态写在每份文档里。例：计算闸口把下单量从 10⁵ 压到 10²–10³ 并提一个数量级成功率 —— **能证明**（`[B09]`、`[B08]`）；"给每个候选跑 μs 级 MD/FEP 预筛比直接合成更省" —— **不能证明**（`[K27]`）；"MD 精筛把命中率从 X% 提到 Y%" —— **尚缺公开同口径基准**。
- **两个证据口径必须分列**（2026-11-07 核过）：
  - 底稿形态 FULLTEXT 87 行（本地有登记全文文件）
  - 卡证据级别 FULLTEXT 79 / DEGRADED 73（卡内逐字核验口径）
  - 差 8 行（`Z01 Z02 Z03 Z05 Z09 C13 C18 M-K29`）：全文在本地但卡按降级写，逐字命中率只有 3/11–32/43，**本轮不升级**。
- **本库不是任何科学结论的担保**。阈值是方法学参考，必须在客户自有体系上按 `protein_design_workflow_iteration.md` 的重校准协议重新验证。

### 许可边界

- 本库**原创部分**（文档、模板、卡里的分析、台账、脚本）：见 `LICENSE`。
- **第三方论文全文不在本仓库，也不在任何发布包里**。本仓库自 2026-11-08 起公开，
  公开 = 公开再分发，所以第三方原文一律不入库（只留在维护者本机）。
  逐篇许可审计见 `deliverables/protein_design_license_audit.md`（87 行，61 行许可允许含商用再分发、26 行不允许）。
  逐份文件登记与重取方式见 `deliverables/fulltext_manifest.csv`（224 份，含 sha256）。
  产品决策是**一律不分发**，理由是义务履行成本与客户侧的一致性。
- 卡片与调研底稿里的英文引句是**引用**，每条带文献编号、出处可查；并且按"引用预算"截短：
  许可受限来源（NC / ND / 出版商条款 / 仅文本挖掘 / 保留所有权利）与许可尚未审计的行，
  引句压到单条 ≤100 字符、同一来源行合计 ≤600 字符（超出后单条降到 50，再超降到 32）；
  可再分发的行（CC BY / CC0）保持原样并履行署名。
  截短有两种口径，账上逐条标明：**逐字命中**（截短结果仍能在来源全文里逐字找到）——
  卡片侧 1,804 条截短**全部**是这一类，逐字核验门禁没有放宽；**原句前缀**
  （本地无全文，或原句是我们自己的转写）——底稿侧 90 条截短里 66 条逐字命中、
  13 条原句前缀、11 条本地无全文·原句前缀。两种口径都只减不增，不新增第三方内容。
  实测：卡 7,125 条引句里受限来源 257,368 → 93,663 字符（−63.6%，1,804 条被截短，涉及 43 张卡）；
  底稿与迭代台账 618 条引句里受限来源 160 条 21,328 → 13,466 字符（−36.9%），
  另有 46 条查不到具体来源行的未归属引句 4,082 → 3,679 字符（合计 25,410 → 17,145，−32.5%，
  90 条被截短，22 条为保住卡片核验链保留原句）。
  未截短的受限引句 106 条逐条登记了原因（`deliverables/quote_budget_exceptions.csv`）。
  逐条账见 `deliverables/quote_budget_ledger.csv`、`quote_budget_summary.csv`、
  `quote_budget_notes_ledger.csv`。
- **整个公开树里第三方逐字引文的总量是实时统计并判定的**（`scripts/audit_public_tree.py`）：
  第三方引句 13,565 处 / 1,251,012 字符，其中许可受限 4,430 处 / 197,459 字符，
  受限来源的单条引句最长 344 字符（上限 400）；清单里标"不随仓库分发"的 220 份第三方原文
  0 份被 git 跟踪。**残余的长引句是公开披露的，不是隐藏的**：106 条超单条上限的受限引句
  逐条写着没截的原因（多数是截断点会落在 markdown 强调段或长单词中间，宁可保留原句）。

### 与"天然 UAA 合成酶发现"主线的关系

本库是**跨实验室判据有效性与成本的参考库**，**不是**那条主线的判定输入。结合体的 `pAE_interaction` / `ipTM` 阈值、适配体 FEP 命中率、展示库通量，都**不得**当成酶活判据或成功概率。那条主线由 `A:\Data\DP2R\方案` 的判定标准管辖，与本库无关。

## 已知的坑（诚实清单）

1. **B28 一行有两张卡**（同一篇 Nature Methods 2025 的早期登记版与后续版）。卡文件 153 个 / 行 152。引用一律以台账 `精读卡文件` 列指向的那张为准。
2. **8 行证据口径差集**（上文已述），卡内逐字命中率不足，本轮不升级。
3. **表格字段曾有 58/152 行与卡片相反**（其中 8 行把"未获正文"写成"全文级"）。2026-11-07 已整列重刷成机器标签，并加了表↔卡一致性门禁；改表走 `scripts/fix_table_fields.py`，改动留账。
4. **RFD4 模型卡的效率表是上一代权重对测的**，当前版本未重测；不能当 RFD4 的效率证据。
5. **许可审计只判"能不能再分发"，不判内容对错**，也不替代法律意见。26 篇受限内容若要商用，需向权利人单独申请。
6. **表级改动账被同日第二次运行覆盖过一次**：早期脚本把账写成按日期命名的固定文件，第二次运行（只改 1 处）把第一次的 152 条记录冲掉。现已由 git HEAD 重放复原 157 条（脚本改为同日合并账目、备份不覆盖），并新增 `scripts/fix_table_fields.py --check` 兜底。
7. **公开克隆里逐字核验判 `WITHHELD` 而不是 `PASS`**：第三方底稿按公开口径不随包分发，
   所以别人克隆仓库后跑 `verify_literature_cards.py` 会看到每行"底稿不在场、无法复核"。
   这不是失败，是口径；本地工作树（有第三方底稿）才是 `PASS_LOCAL 152/152`。
   复核路径写在 `deliverables/fulltext_manifest.csv`（224 份，含 sha256 与重取方式）。
   实测（把本仓库克隆到一处干净目录后逐条跑 13 道门禁）：**退出码全部为 0**，
   `verify_literature_cards.py` 判 `PASS_LOCAL 72/152 · WITHHELD 80 · FAIL 0`；
   两道引用预算门禁把"底稿按公开口径未随仓库分发"记 `WITHHELD` 而不是 `FAIL`；
   `build_workflow_evidence.py --check` 的逐字节比对在行尾 CRLF/LF 归一后进行
   （Windows 检出会把 LF 转成 CRLF，那是平台产物不是内容差异）。
   同一处故意改坏一条引句后 `verify_literature_cards.py` 立刻报 `FAIL 1`——门禁没有因此放宽。
8. **公开前改写了 git 历史**：仓库在私有阶段推送过含第三方全文的提交。转为公开前用
   `git filter-branch --index-filter` 把 220 份第三方原文从全部 18 个历史提交的索引里移除，
   再删 `refs/original/*`、清 reflog、`gc --prune=now`（实测：全历史 `rev-list --objects --all`
   已无第三方原文路径，旧提交对象在本仓库不可达；改写前的完整历史另存本机
   `archive/prepublic-history-2026-11-08.bundle`，已被 gitignore 排除、不随仓库分发）。
   **但 GitHub 对已推送过的对象通常仍按 SHA 保留一段时间**，直接按旧 SHA 或旧路径访问
   仍可能取到内容，直到 GitHub 后台清理完成。所以本库把第三方内容的唯一合法入口指向
   `deliverables/fulltext_manifest.csv` 的重取方式与 sha256，而不是指向任何 GitHub URL。
9. **两件第三方文件是随包分发的**：RFD4-Proteina 的官方 README 与 HuggingFace model card
   （BSD 3-Clause，允许再分发）。上游许可证原文已一并取回放在
   `data/interim/rfd4_2026-11-07/LICENSE-BSD-3-Clause.txt`，署名见 `NOTICE` 第 3 节。
   完整迁移包随这两件走，AI 投喂包不含（它只带 LICENSE 原文与 PROVENANCE），两边都不构成
   第三方全文再分发。

## 怎么验这份东西是不是真的

所有门禁都可以在本地重跑，不需要相信我们的说法：

```bash
python scripts/verify_literature_cards.py        # 152/152 PASS；每条引句在底稿里逐字命中
python scripts/verify_workflow_template.py       # 引用可查 + 87 条阈值都带 P0–P5 与出处
python scripts/verify_workflow_template.py --selftest   # 四种破坏各红一条
python scripts/build_workflow_evidence.py --check # 三个产物与重算结果一致（行尾 CRLF/LF 归一后逐字节比）
python scripts/build_workflow_visual.py --check   # 页面无手打数字，期望值从门禁现算
python scripts/audit_source_licenses.py --check   # 许可审计逐行与重算一致
python scripts/fix_table_fields.py --check       # 表级改动账：账里新值==当前表，受管列每处改动都有账
python scripts/build_fulltext_manifest.py --check  # 第三方原文清单：224 份的 sha256 与磁盘一致
python scripts/apply_quote_budget.py --check       # 卡片引用预算：改动账与卡现状一致，且被截短处仍逐字命中底稿
python scripts/apply_note_quote_budget.py --check  # 底稿引用预算：改动账与底稿现状一致，卡核验链未破
python scripts/audit_quote_budget_exceptions.py --check  # 例外表：超上限却未截短的受限引句逐条有原因，且没有"可截未截"
python scripts/audit_public_tree.py                # 公开树：第三方原文 0 份被跟踪；受限引句单条 ≤400 字符
python scripts/audit_public_tree.py --selftest     # 三种破坏各红一条
python scripts/build_bundles.py --check           # 包内清单与磁盘 sha256 一致
```

任一条退出码非 0，就说明这份东西没做完。**门禁能红，是它可信的前提**——这一点我们在建卡首轮就验过（故意写坏 3 条引句，门禁立刻 FAIL），
2026-11-08 又对引用预算门禁做了同样的负测（改坏一条被截短的引句 → 长度与逐字命中两条判据同时报红，改回后重新 PASS）。
